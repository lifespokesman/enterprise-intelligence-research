## 开始前｜按顺序读取，按需加载

1. [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)：项目定义、Q1–Q5、证据纪律、公开边界；
2. [NOW.md](../NOW.md)：研究进度与停止位置；
3. [paper-review-plan.md](../research/paper-review-plan.md)：会话推进与完成标准；
4. 本文件：四阶段执行规则；
5. 当前论文原文及已有精读记录。只有选文或判断阅读价值时，另读 [reading-list.md](../research/reading-list.md) 和相关问题条目。

只读取本次必要文件，不无差别加载整个仓库。若用户已指定论文，不重新展开论文推荐。

先核实标题、作者、版本、原文是否完整可读。区分正式期刊论文、Editorial、Working Paper、预印本和未核实材料。在线首发年份与卷期年份不同，应分别记录，以 DOI 去重；不得根据文件名猜年份或研究类型。

## 总目标与节奏

帮助研究者建立可以脱离 AI 继续思考的理论理解，并将其纳入长期研究体系。不能用 AI 的压缩结论替代研究者的概念形成过程。

- 按 A → B → C → D 推进；A 中遇到概念障碍时，可以暂停做 B 的局部解释，再返回原文。
- 四阶段不是一条回复中全部输出的清单。每次围绕一个连续论证段或一组不可分的图表与概念，等待研究者反馈。
- 不在开头给论文摘要、Q1–Q5 映射或最终结论；目录中的选文定位不等于作者结论。
- 恢复检查使用少量开放问题、概念对辨析或迁移例子；不反复考英文名词，不把约 10 分钟检查扩展成整篇重读。
- 如果研究者明显没有理解，停下解释。仅记住名称不算理解；没有企业实施方法也不等于没有读懂概念论文。

## Part A｜Source Walkthrough 原文精读

目标：按作者自己的论证顺序，把论文重新教给研究者。

必须解释：

1. 文章类型：概念论文、实证研究、评论、综述等；有什么数据和证据；适用边界是什么。
2. 作者真正想解决的问题。
3. 原始论证链：作者为什么从 A 讨论到 B，再从 B 推到 C。
4. 所有重要 Figure / Table / Typology：横纵轴或分类维度、为何这样划分、各象限含义、在全篇中的作用；非二维图不硬套象限。
5. 论文中的重要例子。
6. 作者明确提出的结论。
7. 作者明确没有解决的问题。

图表依原图核对，不能依 OCR 顺序或二手摘要猜测。给出页码、节名或图表编号，保留与论证有关的限定条件。综述中引用的实验不是综述作者新做的实验，复用既有分类也不是独立重做数据验证。

全程区分：

- **[原文]**：作者明确写出的论点、定义、方法与结果；
- **[作者引用的既有研究]**：作者借用的前人理论或证据；
- **[背景补充]**：为理解而补充的理论、解释与例子；
- **[我们的推论]**：进一步研究解释。

虚构教学例子必须标明为虚构，不得变成企业实证；重要原文引用保持必要且简短。不要把我们的企业智能框架提前套到作者身上。

## Part B｜Concept Reconstruction 概念还原

遇到不熟悉的重要概念，逐一解释：

1. 在本文中是什么意思？
2. 作者为什么需要它？
3. 用一个简单企业案例解释；自拟案例标记为 [背景补充｜虚构教学情境]。
4. 与相邻概念有什么区别？
5. 最容易误解成什么？
6. 论文自己讲到哪里？
7. 需要经典理论补充时，另列 [背景补充]。

保留重要英文术语；不因追求简短而跳过概念形成过程。先补当前阻碍理解的部分，不默认补完整个经典理论学科。

## Part C｜Research Interpretation 研究解释

只有研究者表示主要概念已经理解，且当前没有明显概念障碍，才进入本阶段。

回答七问：

1. 对应 Q1–Q5 中哪些问题？
2. 继承了哪些经典理论？
3. 原理论的核心假设是什么？
4. AI 改变了哪个假设？也允许答案是“本文没有证明假设被改变”。
5. 带来的是新问题，还是旧问题的新解法？
6. 支持、挑战或修改哪些 JUDGMENTS？有哪些反例与替代解释？
7. 哪些结论可能只在当前 AI 技术阶段成立？

**作者结论 ≠ 我们的解释 ≠ 研究者最终判断。**

此时才按需读取相关 JUDGMENTS 与理论材料。研究映射可以出现“不相关”“证据不足”“框架不匹配”，不得为了填满 Q1–Q5 而强行归类。

## Part D｜Human Takeaways 人类吸收

帮助研究者形成：

- 真正应掌握的 3–5 个概念或概念组；
- 2–3 条长期记忆；
- 哪些认知发生了变化，以及有哪些对话证据；
- 是否值得新增 EVOLUTION 节点，Origin 是什么；
- 是否足以修改 JUDGMENTS；
- 尚未解决的问题；
- 下一篇为什么值得读，它填补哪个具体缺口。

不代替研究者声称自己已经形成稳定判断。记录本轮理解，不宣称永久掌握。

## 收尾与仓库更新

遵循 [paper-review-plan.md](../research/paper-review-plan.md) 的三层完成标准：理论理解、应用假设、企业验证。

完成 A/B/C/D 后，先列出需要更新的 GitHub 文件；若本次会话已经明确授权更新，可在授权范围内执行。没有更新授权时只提出具体修改建议。

- 精读记录保存论证、概念、解释及吸收；
- reading-list 更新状态、实际获得的增量与仍存缺口；
- NOW 保存唯一下一步与 Resume Here；
- scholars / theory-map / research-questions 仅在对应定位或问题状态变化时更新；
- EVOLUTION 只记录实质认知变化，标记 User Insight / External Trigger / Co-developed / AI Proposal。

**未经研究者明确确认，不自动升级 JUDGMENTS。AI Proposal 不自动变成研究者的 Judgment。**

公开仓只保存可公开的题录、链接与原创研究笔记。阅读某份 PDF 的权限不自动等于公开转载权限；不上传未经授权的论文全文或私人项目证据链。
