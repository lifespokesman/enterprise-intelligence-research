# Products & Company Philosophy｜产品与公司哲学

本目录研究**产业界如何理解企业 AI 问题，以及这些判断如何被工程化成产品机制**。

这里不是传统竞品功能清单，而是把产品当成一种“可运行的组织假设”。

一个产品研究卡建议回答：

1. **Problem Definition**：这家公司认为企业 AI 的核心问题是什么？
2. **Product Mechanism**：它把哪些能力做成了稳定产品机制？
3. **Product Philosophy**：它反复强调哪些原则、概念或设计语言？
4. **Organizational Assumption**：这些机制隐含怎样的 Human–AI / Agent–Software / Agent–Enterprise 关系？
5. **Q1–Q5 Mapping**：它主要在解决决策权、责任、协调、企业边界还是组织学习？
6. **Evidence**：哪些是公开文档可核验的 Product Fact，哪些只是 Product Claim？
7. **Cases**：有没有真实客户案例支撑？案例来自厂商自己还是独立来源？
8. **Boundary**：哪些机制可能只是当前技术阶段的产品选择，而不是长期不变量？
9. **Challenge to Us**：它支持、挑战还是修改本项目已有 JUDGMENTS？
10. **Engineering Implication**：如果这个产品假设成立，对企业智能工程意味着什么？

## 特别注意

必须严格区分：

- **Product Fact**：公开文档能够确认的具体机制、架构、功能或运行方式；
- **Product Philosophy**：公司公开表达的设计原则和问题定义；
- **Product Claim**：公司对价值、优势、未来趋势的主张；
- **Case Evidence**：客户或第三方公开披露的实际使用事实；
- **Our Interpretation**：本项目对产品背后组织假设的解释。

不能把“厂商把某机制做成产品”直接推导成“该机制已经被产业证明为正确”。

## 适合研究的对象

后续可按当前研究问题选择性研究，例如：

- Palantir AIP / Ontology；
- Microsoft Copilot / Agent / Fabric 等企业 AI 体系；
- Salesforce Agentforce；
- ServiceNow AI / Workflow / Agent 路线；
- OpenAI、Anthropic 等企业 Agent 与工具调用路线；
- 国内具有代表性的企业 AI、智能体、本体、工作入口与运行治理产品。

不按厂商热度建卡，只在某个产品能够帮助回答当前 Q1–Q5 时进入研究。
